# 用户使用说明

## 1. 选择模式

- **演示模式：** 显示预设餐食插画与样例数据，不调用模型、不读取上传图片。页面会明确标注样例结果。
- **真实 AI 模式：** 使用已配置的 DeepSeek API。遇到短暂限流、超时或服务繁忙时会自动重试一次；仍失败时会显示可操作的错误提示，不会改用样例结果冒充真实识别。

## 2. 识别和编辑食材

在“食物识别”页，真实 AI 模式下上传一张餐食图片并点击“识别食材”。支持 JPG、PNG、WebP，以及手机常用的 HEIC/HEIF。应用会在内存中校正方向并压缩为 JPEG，然后发送给模型；不会将图片写入项目磁盘。核对识别名称和份量后，可逐项修改、添加或勾选删除，保存后页面会按本地数据重新计算。

如果上传文件卡片出现红色感叹号，表示浏览器尚未完成文件传输，模型还没有收到图片。请重新选择文件并保持页面和网络连接；如果仍失败，可将照片另存为 JPG/PNG 后重试。若上传成功但识别失败，页面会显示模型服务的具体错误类别。

图片会发送至 DeepSeek 处理。应用不将图片保存到项目磁盘或长期饮食记录中；第三方服务的数据处理受服务商政策约束。不要上传含人脸、地址、病历或其他敏感信息的图片。

若食材没有匹配的本地营养数据，页面会显示缺失名称并将数字标为已知食材小计。可将名称改为目录中的食材，或等待后续补充数据；不能把该小计当作完整总量。

## 3. 推荐菜谱

在“菜谱推荐”页设置口味、时间和难度，点击“为我推荐 / 换一批”。只用确认的非调味食材（食用油、酱油、大蒜、生姜不单独计为匹配）查找相关菜谱；卡片会区分已有食材和仍需准备的用量。真实 AI 模式只有在本地匹配不足时才补充候选，候选必须包含至少一种已确认主食材，只能使用目录内食材，营养仍由程序重算。没有匹配时会明确提示，不会退回显示无关菜谱。

## 4. 规划一餐

填写热量上下限、菜品数量、必须包含和排除的食材、软性饮食偏好、烹饪时间上限及已知过敏原。当前总时间按每道菜标注分钟数相加。

热量、菜品数、食材限制、过敏原和总时间都是硬约束。无法找到符合条件的方案时，页面会明确提示并建议调整输入，不会自动放宽条件。清淡、少油、素食倾向是软性排序偏好，不构成保证。

过敏原筛查依赖目录中已知的成分标记，不能保证排除交叉污染、隐藏配料或数据缺失中的过敏原。对严重过敏风险，请勿依赖本应用作安全判断。

## 5. 使用限制

- 当前数据集较小，主要覆盖常见中式家常食材和菜谱。
- 份量无法由单张照片精确测量；隐藏油、糖和酱料可能识别不到。
- 不提供疾病治疗、体重管理处方或个体化医疗建议。
- 用户填写内容只保存在当前浏览器会话状态，不提供长期保存或跨设备同步。
